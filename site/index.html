Get started

Install, add a key, commit.

Gitable lives in the activity bar. There is nothing to sign up for: bring an API key from the provider you already use and the panel is ready.

Install the extension

From the Marketplace, or straight from your terminal.

$ code --install-extension piyushdoorwar.gitable

Pick a provider and save your key

Open Settings in the Gitable panel, choose OpenAI, Gemini or Claude, and hit Save & Validate. The key goes into VS Code SecretStorage and the live model list loads.

Stage and generate

Check the files that belong together, move them to Staged, and press the sparkle in the summary field. Edit the draft if you like, then commit.

Other editors

Gitable runs anywhere VS Code extensions do, including Cursor and Windsurf. Install the same way from your editor's extension view.

Control the token budget

Settings → Config sets how much diff each AI call may send (Low, Mid or High). Lockfiles, build output and other generated files are filtered out first.

Features

Git work, gathered into one panel.

The everyday loop stays visible: inspect files, stage the right changes, write the commit, and sync.

Visual staging

Working, Staged and Stashes sit under one Changes tab, in a flat list or a folder tree, with bulk stage, unstage and discard.

AI commit messages

A summary and description drafted from the staged diff, with an optional prefix such as a JIRA-123 key.

Bring your provider

OpenAI, Gemini or Claude with your own key, and a model list fetched live from the provider.

History and summaries

Expand any commit to see its files, select a range with shift-click, and get a plain-English summary of what changed.

Security review

Scan staged changes, the working tree or selected commits for risky code, with findings ranked by severity.

Branches and sync

Separate pull and push buttons with ahead and behind counts, publish with upstream, and a guided choice when branches diverge.

Conflicts and rebase

Conflicted files get their own section with merge-editor and mark-resolved actions, plus Continue and Abort for rebases.

Stashes with notes

Stash staged work or selected files, then pop, apply or drop it later. Add a note so you remember what each stash holds.

Tags, amend and undo

Create and push tags, amend the last commit, undo an unpushed commit, revert or cherry-pick, and force-push with lease.

Workflow

From changed files to a reviewed commit.

Every AI feature reads only the diff you point it at. Review it like any other suggestion, then commit with confidence.

  • Open any file's diff in VS Code's native diff editor, straight from the list.
  • Run a security review before you commit, or on a range of commits before you merge.
  • Unpushed commits are marked in History, so you always know what still lives only on your machine.
  • Optional Jira panel: see your open issues, then create a branch or commit prefix from one.

Privacy first

Your repository stays on your machine.

Gitable has no backend. The only thing that leaves VS Code is the diff you choose to send, and it goes straight to your provider.

No extension server

AI requests go from VS Code to the provider you configured. Gitable does not proxy, log or store them.

SecretStorage keys

API keys and Jira tokens live in VS Code SecretStorage, never in settings files or your repository.

You choose the diff

Generation reads the staged diff only, filters generated files and caps the size to your token budget.

No telemetry

There is no analytics pipeline. Usage reports are computed locally to help you understand your own AI calls.
